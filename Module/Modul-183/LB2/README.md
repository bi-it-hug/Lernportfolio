# LB2: Praxis-Arbeit

Für die LB2 existieren mehrere Ansätze:

- Projektarbeit klassisch (so wie das Modul vor der BiVo21 definiert war): Eine Gruppe von Lernenden wählen ein bestehendes Projekt, welches den Mindestanforderungen entspricht (oder entwickeln kurz eines - muss nichts Aufwendiges sein). Dann wird das Projekt einer anderen Gruppe von Lernenden zum Testing übergeben. Die machen ein klassisches Penetrationtesting mit der Applikation und schreiben Testberichte. Die Gruppe die, die Applikation zur Verfügung gestellt hat, behebt im letzten Teil des Projekts die gefundenen Schwachstellen (oder begründet fachlich korrekt, wieso diese nicht behoben werden). [Zu den Unterlagen](Projektarbeit_klassisch)
- Projektarbeit geführt (mit containerized app): Die Lehrperson gibt eine Applikation vor, die selbst Schwachstellen enthält. Diese muss erweitert werden. Während dem Erweitern soll die Gruppe bereits möglichst viele Schwachstellen ebenfalls identifizieren und eliminieren. Die Applikation wird einer anderen Gruppe zum Pentesting übergeben. Diese erstellt ein Testprotokoll, welches alle vorgenommenen Tests enthält und dokumentiert, welche Arten von Schwachstellen noch gefunden bzw. nicht gefunden wurden. In einem letzten Schritt fixt die Gruppe, dessen Applikation getestet wurde, die noch gefundenen / vorhandenen Schwachstellen. [Zu den Unterlagen](Projektarbeit_container)

- Kleinere Übungsaufgaben die Bewertet und zur Gesamtnote der LB2 verrechnet werden: Entspricht eher dem SOL-Gedanken. Die kleineren Übungsaufgaben sollten mehr oder weniger unabhängig voneinander sein und es aber auch nicht erlauben die Lösungen anderer zu kopieren (also ein gewisser Grad an Individualität aufweisen). **Dieser Ansatz muss noch ausdefiniert / ausgearbeitet werden.**
