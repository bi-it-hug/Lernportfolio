# Projekt-Kontrolle-Vorgangsmodelle

## SCRUM

SCRUM ist **kein Modell oder eine Technik an sich**, sondern ein **agiles Framework** für die Projekt- und Produktentwicklung. Es basiert auf empirischer Prozesssteuerung (Transparenz, Inspektion, Adaption) und nutzt bestimmte **Praktiken, Techniken und Artefakte**, um iterative und inkrementelle Wertschöpfung zu ermöglichen.

Hier eine Übersicht über die **zentralen Elemente, Techniken und unterstützenden Modelle**, die SCRUM verwendet:

### **1. SCRUM-Artefakte (mit Techniken zur Pflege)**

| Artefakt            | Zweck                                                | Wichtige Techniken                                                                                                                                                 |
| ------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Product Backlog** | Priorisierte Liste aller gewünschten Features        | **Backlog Refinement (Grooming)**, **User Story Mapping**, **MoSCoW-Priorisierung**, **DEEP-Kriterien** (Detailed appropriately, Emergent, Estimated, Prioritized) |
| **Sprint Backlog**  | Auswahl für den aktuellen Sprint                     | **Task Breakdown**, **Definition of Ready (DoR)**                                                                                                                  |
| **Increment**       | Fertiges, potenziell auslieferbares Produktinkrement | **Definition of Done (DoD)**, **Continuous Integration**                                                                                                           |

### **2. SCRUM-Events (mit eingesetzten Techniken)**

| Event                    | Dauer    | Häufig genutzte Techniken                                                                                          |
| ------------------------ | -------- | ------------------------------------------------------------------------------------------------------------------ |
| **Sprint Planning**      | 2–8 Std. | **Planning Poker**, **Story Points**, **Velocity-basierte Planung**, **Affinity Estimation**                       |
| **Daily Scrum**          | 15 Min.  | **Walking the Board**, **Three Questions**, **Parking Lot**                                                        |
| **Sprint Review**        | 1–4 Std. | **Demo**, **Stakeholder-Feedback**, **Increment Inspection**                                                       |
| **Sprint Retrospective** | 1–3 Std. | **Start-Stop-Continue**, **4L (Liked, Learned, Lacked, Longed for)**, **Sailboat**, **Mad/Sad/Glad**, **Timeline** |

### **3. SCRUM-Rollen (mit impliziten Techniken)**

- **Product Owner**: Nutzt **Impact Mapping**, **Kano-Modell**, **Value Proposition Canvas**
- **Scrum Master**: Wendet **Facilitation**, **Coaching**, **Konfliktlösung**, **Impediment Removal**
- **Entwicklungsteam**: Nutzt **Pair Programming**, **TDD**, **Swarming**, **Cross-Functionality**

### **4. Unterstützende Modelle und Konzepte**

| Modell/Konzept                  | Anwendung in SCRUM                                            |
| ------------------------------- | ------------------------------------------------------------- |
| **Empirische Prozesssteuerung** | Kernprinzip: Transparenz → Inspektion → Adaption              |
| **Lean Thinking**               | Waste-Reduktion, Value Stream Mapping                         |
| **User Stories**                | Format: _„Als [Rolle] möchte ich [Funktion], damit [Nutzen]“_ |
| **Story Points & Velocity**     | Relative Schätzung (Fibonacci), Kapazitätsplanung             |
| **Burndown Charts**             | Fortschrittsvisualisierung                                    |
| **Definition of Done (DoD)**    | Qualitätsgate für Increments                                  |
| **Definition of Ready (DoR)**   | Reifegrad für Backlog-Items                                   |

### **5. Technische Praktiken (oft kombiniert mit SCRUM)**

Obwohl SCRUM **technik-agnostisch** ist, werden häufig ergänzt:

- **Test-Driven Development (TDD)**
- **Continuous Integration / Continuous Delivery (CI/CD)**
- **Pair Programming**
- **Code Reviews**
- **Refactoring**

### Zusammenfassung: SCRUM **bedient sich**...

- **Keiner starren Modelle**, sondern eines **Frameworks**
- **Empirischer Steuerung** (Transparenz, Inspektion, Adaption)
- **Iterativer und inkrementeller Entwicklung**
- **Vielfältiger Techniken** wie Planning Poker, Retrospektiven, User Stories
- **Artefakten** wie Backlogs und Increments
- **Unterstützender Konzepte** aus Lean, Agile und Software Craftsmanship

> **Merksatz**: _SCRUM ist das „Was“ und „Wann“ – die Techniken sind das „Wie“._
